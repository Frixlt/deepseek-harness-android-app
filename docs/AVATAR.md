# Аватар оверлея

В консоли → «Оверлей» доступны классическая картинка, шесть спрайтов и Live2D.
Размер: 40–360 dp; на небольших экранах верхняя граница ограничивается шириной
экрана минус 24 dp. Новый размер по умолчанию для персонажа — 160 dp.
Сохранённый пользователем размер сохраняется после обновления.

Для Live2D доступны исходные чиби и большая модель с авторским ригом.
Жесты и эмоции используют имеющиеся параметры рук, глаз и лица.

**Сидячая поза по референсу не реализована.** Экспериментальная деформация стоячего
рига удалена: она растягивала ноги/юбку и не являлась полноценным риггингом.
Для корректного результата нужны подготовленные слои сидячих ног и одежды,
отдельные меши/деформеры и новый экспорт модели из редактора.
В исходном ZIP есть послойный PSD; проекта редактора `.cmo3` нет.
Исходные MOC и текстуры не изменены.
Спрайтовый режим использует имеющиеся шесть картинок.

Состояния: покой, размышление, ответ, поиск, чтение, редактирование, браузер,
наблюдение за экраном, терминал, общий инструмент, подключение, вопрос пользователю,
завершение задачи, прощание, ошибка, пауза, сонливость, отключение.
Структурированные события и имена инструментов определяют эмоцию независимо от
перевода/пользовательского текста. Закрытие подписи не сбрасывает эмоцию.
Кнопки предпросмотра показывают эмоцию на три секунды и возвращают рабочее состояние; реальные события сразу прерывают предпросмотр.

## Локальная модель

Плеер (`android-app/overlay-player/`) включён в APK и обновляется вместе с приложением.
Лицензированные модель и библиотеки Cubism/PIXI хранятся отдельно от Git/APK:

```
/sdcard/deepseek-harness/live2d/
  index.html
  live2dcubismcore.min.js
  pixi.min.js
  cubism4.min.js
  model/*.model3.json
  model/*.moc3
  model/*.physics3.json
  model/*.cdi3.json
  model/.../texture_*.png
```

Поддерживаются также `getExternalFilesDir()/live2d` и `getFilesDir()/live2d`.
Общая директория `/sdcard/...` требует разрешения приложения на доступ к файлам.
Уже установленная модель продолжает работать после обновления APK.

Подготовка/обновление существующего частного пакета и отправка по ADB:

```sh
bash tools/deploy-live2d-device.sh /path/to/original-model.zip
```

Переменные `AVATAR_CACHE_DIR`, `AVATAR_RUNTIME_DIR`, `ANDROID_SERIAL`, `ADB`
позволяют указать другой каталог, ранее полученные JS-библиотеки и устройство.
Если модель ещё не установлена, Python-скрипт извлекает только необходимые файлы
из ZIP, сохраняет прозрачность/UV и уменьшает текстуры до 2048 пикселей по большей
стороне (нужен Pillow). PSD, настройки VTube и лишние превью не копируются.
Без библиотек скрипт завершается с понятной ошибкой; автоматического скачивания
лицензированного SDK нет. Без устройства готовый пакет остаётся для ручного копирования.

## Производительность и регрессии

Область касания ограничена alpha-силуэтом, включая прозрачные промежутки; пустые участки пропускают нажатия. Узкое окно полноразмерной модели рассчитывается по видимым пропорциям, а не по квадрату. Индикатор размышления использует анимационный параметр исходного рига `Param140`.

WebView создаётся только для Live2D, уничтожается при смене режима/остановке сервиса.
Плеер ограничен 30 FPS; качество выбирается отдельно: экономия, стандартное, высокая чёткость под родной экран и максимальное сглаживание (буфер ограничен 2048 px по стороне). При скрытии плеер останавливает свой ticker, не затрагивая
таймеры браузера/чата. Видимый силуэт измеряется по alpha при загрузке/смене телосложения,
а изменение размера пересчитывает масштаб без повторной загрузки модели.
Шапка, волосы и руки получают запас внутри кадра.

```sh
javac -d /tmp/avatar-state-check android-app/src/com/deepseek/harness/AvatarState.java tools/tests/AvatarStateTest.java
java -cp /tmp/avatar-state-check com.deepseek.harness.AvatarStateTest
node tools/tests/overlay-events.cjs
node tools/tests/avatar-rendering.cjs
# Нужен Playwright; AVATAR_BROWSER при необходимости задаёт путь к Chromium.
node tools/tests/check-avatar.cjs /path/to/private/package /tmp/avatar-renders
bash tools/build-apk.sh
```

Рендер-тест проверяет два исходных телосложения, 16 состояний, шесть размеров при DPR 3.5, четыре уровня качества и alpha-область касания,
восстановление эмоции после нажатия и остановку/возврат ticker.
Для проверки на Android нужны загрузка локальных файлов, смена размеров/телосложения,
перетаскивание, закрытие подписи, смена режима и скрытие приложения.

## Установка без сброса и предкомпиляция

Обновление ставится через `adb install -r` с той же подписью. После установки
ART-код приложения можно предкомпилировать на конкретном телефоне, сохранив данные:

```sh
adb install -r --no-incremental android-app/DeepSeekHarness-community.apk
adb shell cmd package compile -m speed -f com.deepseek.harness.community
adb shell pm art dump com.deepseek.harness.community
```

Успешный результат содержит `status=speed`. Компиляция относится к установленной
версии приложения на устройстве; после следующего обновления её нужно выполнить заново.

Без чтения переписок и настроек можно получить геометрию оверлея, состояние области
касания и проверку вмещения текста в кнопки:

```sh
adb shell dumpsys activity service com.deepseek.harness.community/.OverlayService
```
